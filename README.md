# Template Sync

Template Sync 是一个强大的 Git 历史重建工具。专门用于解决**“由模板创建的项目”与上游模板仓库之间丢失 Git 共同历史**的痛点。

它能够将完全独立的代码拷贝精准物化为有血缘关系的 Git 分支，让您从此告别枯燥且易错的“手工比对复制”，能够优雅地使用标准 `git merge` 或 `git rebase` 命令来合并上游模板的最新更新。

## 核心原理

Template Sync 采用安全、无损、零侵入的分析策略：

1. **优先复用共同历史**：
   整仓同步时先查找当前分支与模板分支的真实共同祖先，包括从合并提交的第二父链进入的历史。找到共同历史后，直接创建指向模板最新提交的本地分支，保留原始提交哈希和签名，只统计当前分支尚未包含的模板提交。分析过程只读，不会获取对象或创建引用。
2. **Parent 拓扑重构 (重写历史)**：
   没有共同历史时，匹配项目起点与模板提交的完整文件树，再将后续模板提交的 parent 指针连接到项目起点。只有父提交或文件树发生变化时才重写提交；未变化的提交原样保留。
3. **安全无损零改动**：
   重构过程只进行读取和生成操作，**绝对不会**改写项目现有的分支或历史记录。最终只会为您在本地生成一个独立的新分支，具体的合并或变基完全交由开发者自行控制。

## 使用场景

日常开发中，我们往往通过下载压缩包或拷贝代码来初始化项目。几个月后，上游模板发布了重大更新（修复了致命 Bug，或推出了新特性）。

由于您的项目脱离了模板的 Git 历史，传统的升级方式极其痛苦：您必须手工逐个比对文件，小心翼翼地把更新内容复制粘贴过来。

**Template Sync 就是为了解决这个痛点而生：它可以为您找回丢失的 Git 历史，重新建立血缘关系。**

## 技术栈与运行模式

本项目是一个全栈 TypeScript 应用程序。为了适应不同用户习惯，系统支持多端运行：

- **命令行模式 (CLI)**：提供高效的终端命令行工具，支持全局配置默认模板仓库、一键极速同步与交互式向导模式。
- **桌面模式 (Electron)**：编译为独立的桌面应用程序，提供更原生的本地文件系统访问体验。

## 命令行工具 (CLI)

### 安装

```bash
npm install -g @lsby/template-sync
# 或使用 pnpm
pnpm add -g @lsby/template-sync
```

### 常用命令与配置

```bash
# 1. 首次使用：设置全局默认模板仓库路径（及可选默认分支）
lsby-template-sync set-template /path/to/template-repo [分支名]

# 2. 查看当前全局配置
lsby-template-sync config

# 3. 日常使用：在基于该模板的项目目录下直接一键同步
cd /path/to/project-repo
lsby-template-sync

# 4. 一键同步并自动合并到当前分支
lsby-template-sync --merge
```

### 命令行选项

```bash
lsby-template-sync [项目路径] [模板路径] [选项]
```

| 选项                        | 简写 | 说明                                                 |
| --------------------------- | ---- | ---------------------------------------------------- |
| `--project <路径>`          | `-p` | 项目仓库路径 (默认: 当前工作目录)                    |
| `--project-prefix <子目录>` |      | 将模板同步到项目仓库内的子目录，留空时保持整仓模式   |
| `--template <路径>`         | `-t` | 模板仓库路径 (覆盖全局默认配置)                      |
| `--branch <分支名>`         | `-b` | 模板分支名称 (默认自动检测 `main` / `master`)        |
| `--output <分支名>`         | `-o` | 输出分支名称 (默认: `template-sync/YYYYMMDD-HHMMSS`) |
| `--merge`                   | `-m` | 嫁接创建完成后直接执行 `git merge`                   |
| `--analyze-only`            |      | 仅执行仓库比对分析，不创建分支                       |
| `--yes`                     | `-y` | 跳过确认提示直接创建分支                             |
| `--interactive`             | `-i` | 强制启用交互式向导模式                               |
| `--version`                 | `-v` | 显示版本号                                           |
| `--help`                    | `-h` | 显示帮助信息                                         |

### 记录已确认的同步起点

模板重写历史后，环境文件等差异可能导致原来的完整文件树无法自动匹配。确认两个提交确实对应同一个模板版本后，可在项目仓库记录一对完整提交哈希：

```bash
git config --local template-sync.project-base <项目历史中的模板提交哈希>
git config --local template-sync.template-base <模板仓库中对应的提交哈希>
lsby-template-sync --analyze-only
lsby-template-sync --merge
```

这对本地配置用于没有共同历史时的嫁接，优先于文件树自动匹配；已有真实共同历史时直接复用历史。两项配置始终必须同时存在且有效，项目提交必须属于当前 HEAD 的历史，模板提交必须属于所选模板分支的历史。配置代表您已确认这两个版本的对应关系，工具不会要求它们的文件树完全相同，因此应使用原始模板导入提交，避免把业务修改误认为模板内容。配置仅支持整仓同步，不会随 Git 提交传给其他克隆；恢复自动匹配时同时运行 `git config --local --unset template-sync.project-base` 和 `git config --local --unset template-sync.template-base`。

### Monorepo 子目录同步

当模板作为 monorepo 内的一个子目录存在时，可以指定项目子目录：

```bash
lsby-template-sync --project /path/to/monorepo --template /path/to/template --project-prefix packages/web
```

工具会在项目第一父历史中寻找该子目录与模板提交完全一致的基线，并将后续模板提交投影到该子目录。项目仓库内的其他目录不会进入模板更新差异。为确保工具能够自动找到基线，应先原样提交一次模板副本，再在后续提交中进行项目重命名和业务定制。

使用已配置默认模板的一键命令时，如果当前目录就是 Git 根目录，工具会保持原有的整仓同步行为；如果当前目录位于 Git 仓库的子目录中，交互式终端会询问是否仅同步当前子目录。非交互环境不会自动推断范围，脚本调用时请显式传入 `--project-prefix`。

## 注意事项

- 界面与命令行默认会生成带有时间戳的安全分支名称（如 `template-sync/20260731-120000`）。您可以自定义名称，系统会保证不会覆盖已存在的同名分支。
- 复用共同历史时，模板提交哈希和签名完整保留。嫁接时，父提交或文件树变化会改变提交哈希，相关提交的旧签名会被移除。
- 本工具旨在生成一条规范的分支供您合入，实际的合并(Merge)和代码冲突解决仍使用您最熟悉的标准 Git 工作流进行。
